# Decisions

Why things are the way they are. Most of these were learned the hard way while
installing the home PC on 3 Oct 2026; the original install runbook is the
"Menadion Migration" artifact.

## Tooling

- **lodestar, our own tool, for everything** (since 21 Oct 2026; before, chezmoi
  for `$HOME` and aconfmgr for the system). The design and its reasons are in
  [tool-design.md](tool-design.md); `lodestar drift` keeps "every change is in
  the repo" checkable, without root.
- **KDE settings as single keys, not files.** Plasma rewrites its rc files on
  every change (window geometry, timestamps, migration markers), so whole files
  would drift constantly. Modules hold only the keys changed on purpose
  (`kde:`); `lodestar kde review` shows what changed in System Settings.
- **No secrets in the repo, even encrypted.** The repo is public and git
  history is permanent; an encrypted secret is only safe until its key leaks.
  Secrets stay in Bitwarden and are fetched at apply time.
- **Official Bitwarden CLI (`bw`) over `rbw`.** `rbw` is faster and has an
  agent, but it is third-party code handling the master password. lodestar
  runs `bw unlock` only when a template needs a secret.
- **SSH keys per machine.** Nothing to restore on a new machine; a lost machine
  means revoking one key.

## Boot (home PC)

- **Limine on the shared ESP**, entries generated by `limine-entry-tool`
  (`limine-mkinitcpio-hook`), snapshot entries by `limine-snapper-sync`.
  Limine reads only FAT, so kernels live on the 4 GiB ESP.
- **`ENABLE_VERIFICATION=yes`**: every kernel and initramfs path in
  `limine.conf` carries its BLAKE2B hash, which Limine checks before loading.
  The config's own hash is enrolled into the loader only on wandersail
  (`ENABLE_ENROLL_LIMINE_CONFIG`, below); then a hand edit must be followed by
  `limine-update`, or Limine stops with a checksum error.
- **`FIND_BOOTLOADERS=no`**: otherwise the tool adds a *Systemd-boot* entry
  (dead after NixOS was removed) and an *EFI fallback* entry that chainloads
  Limine into itself.
- **`ENABLE_LIMINE_FALLBACK=yes`**: keeps `EFI/BOOT/BOOTX64.EFI` current. The
  MSI firmware sometimes boots that copy rather than the named entry.
- **`remember_last_entry: yes`, no `default_entry`, `timeout: 1`.** Remembering
  is what makes hibernation work on both OSes: an unattended power-on returns to
  the OS that was hibernated. Deliberate switching uses one-shot entries, which
  do not touch the remembered one. Not `timeout: 0`: the menu is the only way
  to reach the snapshot entries.
- **OS switching via `bootctl set-oneshot`**, not `systemctl reboot
  --boot-loader-entry=`: logind only accepts entries it finds as BLS files on
  the ESP, and Limine has none. The one-shot takes Limine's entry *id*
  (`Arch-Linux.linux`, `Windows-11`), not the menu title.
- **`limine.conf` is half generated, half hand-written.** The tools own the
  Arch Linux entry and the Snapshots group; the global options and the Windows
  entry are ours, kept in `hosts/menadion/limine.conf` (`boot.limine`) and
  merged in by lodestar, which then runs `limine-update` to re-enroll the hash.
  lodestar never manages `/boot` otherwise: it changes with every snapshot.
- **Rebuild with `limine-mkinitcpio`**, not `mkinitcpio -P`. The package
  replaces the stock pacman hook, so `/boot/initramfs-linux.img` is never
  updated and plain `mkinitcpio` does not update Limine's entries.

## Secure Boot and TPM unlock (work laptop)

- **Our own keys (sbctl), Microsoft's kept** (`enroll-keys -m`): HP firmware
  and option ROMs are signed by Microsoft; removing them risks a dead GPU or
  dock at POST.
- **The chain**: the firmware checks Limine's signature; Limine checks
  `limine.conf` against its enrolled hash and every kernel/initramfs against
  the hash in its path. With Secure Boot on and a hash enrolled, Limine also
  disables its editor and the UEFI shell, so the kernel cmdline cannot be
  changed at boot. limine-entry-tool re-enrolls and re-signs after every change
  (`/etc/boot/hooks`, run by limine-snapper-sync too).
- **TPM policy: PCR 7 only.** It holds the Secure Boot state and the
  certificate that authorized each image, so the TPM unlocks only after a boot
  through Limine signed by our key (a Microsoft-signed loader records a
  different certificate). PCR 8 (Limine's cmdline) and 9 (kernel, initramfs,
  config) would change with every cmdline edit, kernel update or snapshot entry.
- **fwupd boots its own signed binary** (`DisableShimForSecureBoot`): shim
  only trusts Microsoft's and the distribution's keys, not ours. fwupd cannot
  apply Microsoft's KEK updates any more (they must be signed by the PK, now
  ours); db and dbx updates still apply, signed by Microsoft's KEK.
- **The passphrase stays** as a LUKS key slot: it is the fallback whenever
  PCR 7 changes. The kernel is not in lockdown (Arch does not tie lockdown to
  Secure Boot), so hibernation keeps working.

## initramfs (home PC)

`MODULES=(btrfs hid_logitech_dj hid_logitech_hidpp)`

- **No NVIDIA modules.** With them loaded from the initramfs (early KMS) and
  `NVreg_PreserveVideoMemoryAllocations=1`, the resuming kernel cannot freeze
  the GPU (`pci_pm_freeze returns -5`) and the hibernated image is discarded.
  Loaded later from the root filesystem, resume works. Cost: a brief mode switch
  at boot. `nvidia_drm.modeset=1` stays on the kernel command line.
- **Logitech receiver drivers.** Without them `hid-generic` claims the G305's
  Lightspeed receiver at ~5 s and `logitech-dj` takes over at ~12 s; on about
  2 boots out of 3 the receiver never re-announced the mouse.

## Desktop

- **`plasma-meta` stays, so Discover and Flatpak stay installed but unused.**
  Software comes from pacman and the AUR (yay), which lodestar tracks; Flatpaks
  would live outside `lodestar drift`. `plasma-meta` hard-depends on `discover` and
  `flatpak-kcm` (which needs `flatpak`), and listing its other dependencies by
  hand would miss components added by later Plasma releases.
  `plasma-meta-deflatpak` (AUR) still depends on `discover`.

## DNS

- **Cloudflare over DNS-over-TLS, through `systemd-resolved`**
  (`resolved.conf.d/cloudflare-dot.conf`). It is part of systemd, so there's no
  extra package. NetworkManager uses it because `/etc/resolv.conf` links to its
  stub (127.0.0.53). `no-dhcp-dns.conf` stops NM from passing the router's DNS
  on, or resolved would also query it in plain text. `DNSOverTLS=yes` is strict:
  if port 853 is blocked, DNS fails instead of falling back to plain text
  (`opportunistic` would fall back silently).
- **Not DoH.** DNS-over-HTTPS (tried first, with `dnscrypt-proxy`) encrypts
  the same way; it only also hides that the traffic is DNS, which matters on
  networks that block port 853, not on a home LAN. It cost an extra service and
  a 1,000-line config that drifts from the package's.
- On a network whose internal names need its own DNS (the work LAN, a captive
  portal), add that connection's DNS by hand: `nmcli connection modify <con>
  ipv4.ignore-auto-dns no`.
- **The company VPN uses its own DNS, in plain text** (`modules/work/vpn-dns`):
  its servers' names only exist there, and the server doesn't speak TLS. The
  hook turns DNS-over-TLS off for that connection and makes its DNS first for
  every name while connected (`~.`, priority -50), as NixOS did.

## Hardware (home PC)

- **NVIDIA**: `nvidia-open-dkms`; `options nvidia NVreg_PreserveVideoMemoryAllocations=1`
  (check `journalctl -b | grep 'ignoring bad line'` is empty after editing);
  `nvidia-suspend/hibernate/resume.service` enabled.
- **Flat mouse acceleration for every mouse.** KDE stores it per device; there
  is no global switch, so `modules/kde/flat-mice` (a hook run on every apply)
  writes it for every mouse seen.
- **C: mounted at boot with the new in-kernel `ntfs` driver** (kernel 7.2). It
  mounts a hibernated or dirty volume read-only instead of refusing it. If it
  misbehaves, `ntfs3` is the fallback.
- **Wake-on-LAN does not work from Linux (known `igc` / I225-V issue).**
  NetworkManager arms the NIC (`conf.d/wake-on-lan.conf`,
  `ethernet.wake-on-lan=magic`; `ethtool` shows `Wake-on: g`), the device and its
  root port are ACPI wake sources, and the DSDT has nothing OS-dependent on that
  path (`_PRW` → GPE 0x69, S4). Still, after suspend, hibernate or poweroff from
  Linux the card does not wake; from Windows it does. Ruled out: link speed
  (10/100), `d3cold_allowed=0`, MSI "Wake Up Event By BIOS" + "Resume By PCI-E
  Device". Same unresolved reports for 8086:15f3 on other boards. The config
  stays so it works if the driver gets fixed. The dark port LEDs during sleep
  mean nothing: `igc` drives the LEDs and `led_suspend` turns them off.

## Logitech mice (logi-smartshift)

- **Per-app wheel settings (Options+ style) with our own
  `modules/logi-smartshift`, not Solaar or logiops.** Both broke smooth
  scrolling on the work laptop: logiops diverts the wheel and re-emits coarse
  events, and Solaar re-applies the wheel resolution behind the kernel driver.
  The kernel's `logitech-hidpp` driver already gives hi-res scrolling, so
  logi-smartshift only sends SmartShift (feature 0x2111: threshold + scroll
  force) and never touches wheel events. Neither tool has per-app profiles on
  KDE Wayland anyway.
- **Written in Go** like the old repo's daemons (spotify-vol, mutectl): one
  static binary, `go` only as a make dependency.
- **A KWin script reports the active window**: on Wayland only the compositor
  knows it. The daemon loads the script over D-Bus at start, so nothing in
  `kwinrc` has to enable it.
- **Local package rather than files spread across the module's trees**:
  binary, user unit, KWin script, udev rule (hidraw `uaccess`) and config all
  live in one folder and uninstall together. lodestar rebuilds it when
  `pkg/` changes, so editing the config is enough; no version bumps.
- **Named logi-smartshift, no longer logi-wheel**: an AUR package (a
  racing-wheel tool) is called `logi-wheel`, and yay would replace ours with
  it once its version passed ours.
- **Options+ sensitivity uses Options+'s own formula**: threshold =
  50 + round(-0.46 × sensitivity), read from the disassembly of
  `logioptionsplus_agent.exe` (`devio_feature_xsmartshift`); it matches the 10
  that Options+ wrote for 88. Solaar and logiops only expose the raw threshold.
- **New hidraw nodes are watched with inotify on `/dev`**: switching the mouse
  back to this PC recreates its node, and polling made the profile arrive late.

## mpv

- **One config for Windows and Linux**, at `modules/mpv/config/` in the repo.
  Linux links `~/.config/mpv` to it (`link:`); Windows junctions
  `%APPDATA%\mpv` to a clone (`modules/mpv/windows/Setup-Mpv.ps1`).
  Edits land straight in the git working tree on both sides.
- **No per-OS copies**: the only OS-specific values (screenshot folder) are
  conditional profiles on mpv's `platform` property at the end of `mpv.conf`.
- **Fonts**: subtitle presets bring their own fonts in `config/fonts` (all freely
  redistributable; Roboto Medium is the SubsPlease build, Apache 2.0). Arial and
  Trebuchet MS come from `ttf-ms-fonts` on Linux; the sub-style menu uses the
  bundled Atkinson Hyperlegible Next instead of Segoe UI so it looks the same.
- **Subtitle style defaults to Auto**: SubsPlease look when the audio is
  Japanese (anime), VLC-like otherwise. Styled .ass subs still keep their own
  style. Picking a preset in the menu overrides it until Auto is picked again.
- **Forced subtitle tracks are skipped** (`skip-signs-subs.lua`): streaming
  rips flag the forced track (foreign lines only) as default, so mpv picked it
  over the full one; the script swaps to the full, non-SDH track.
- **Patched ModernZ**: `config/scripts/modernz.lua` carries the sub-style "Aa"
  button; `config/sub-style-modernz-patch.md` explains how to reapply it after
  updating ModernZ.

## Readest

- **Only the keys changed on purpose**, found by diffing Readest's own fresh
  defaults against the Windows `settings.json` (4 Oct 2026). The rest of that
  file is device ids, sync state and open books. lodestar merges (`json:`)
  the keys in (only while Readest is closed, or it overwrites them on exit).
- **Sizes are home-only** (`hosts/menadion/readest.json`): font 40, 144 px margins and the wide
  text block were tuned for the 4K TV and would be too big on the laptop.
- **Reading font: Literata** (serif, `ttf-literata`), on trial from 4 Oct 2026
  after a font research round; Lato stays as the sans font. Bookerly was tried
  and dropped.
- **The library is data, not config**: copied once from Windows to
  `~/.local/share/com.bilingify.readest/Readest/`, not in the repo.

## Remote desktop (home PC)

- **KRDP (Plasma's RDP server), logging in with the Linux account** (PAM,
  `SystemUserEnabled`) rather than a separate RDP user, so no password lives in
  KWallet or the repo. Port 3389; there is no firewall to open. Keys in
  `modules/krdp/module.yaml`; the certificate (self-signed, per machine) comes
  from its hook, `krdp-cert.sh`.
- **Linux-account login turned off again** (11 Oct 2026): `SystemUserEnabled`
  is back at its default (off) and no longer declared. Any RDP user is
  added by hand in System Settings → Remote Desktop.
- **Broken with FreeRDP 3.32 in krdp 6.7.5** (4 Oct 2026): FreeRDP now turns on
  extended security, so clients that offer NLA get it, and NLA looks for the
  user in KRDP's own (empty) user list: "Could not find user in SAM database",
  shown as a wrong password. Fixed upstream in krdp commit 4eb3dff (KDE bug
  526514), not yet in a release. Until then: in Remmina set *Security protocol
  negotiation* to **TLS**; the phone's Windows App cannot, so it waits for the
  fix (or a separate RDP user in System Settings → Remote Desktop).

## Docker

- **docker + docker-compose + docker-buildx from the Arch repos**, not Docker
  Desktop. Rootful daemon; the user is in the `docker` group (`useradd` in
  `user.groups`), which is root-equivalent, accepted on a single-user desktop.
- **Socket-activated** (`docker.socket` only): no daemon at boot until something
  uses it. Containers with a restart policy therefore come back only once the
  socket is first hit; enable `docker.service` too if that ever matters.
- **`/var/lib/docker` is its own subvolume, `@var_lib_docker`**, like
  `@var_log`/`@var_cache`: images and volumes stay out of snapper's root
  snapshots, and a rollback does not roll containers back.

## Discord (work laptop)

- **OpenASAR and Vencord, with the mutectl plugin**, as on NixOS. Arch's
  `discord` package is only a bootstrapper: Discord installs itself into
  `~/.config/discord/app-<version>` and updates itself there, so the mods
  cannot be part of a system package. `modules/discord/pkg` builds them;
  `discord-openasar-vencord` copies them into each `app-*` folder at login
  and after a rebuild. A Discord update during a session keeps Vencord (it
  copies itself over) and gets OpenASAR back at the next login.
- **OpenASAR without `EnableDrDc`**: its "perf" preset turns DrDc on, and with
  VA-API decode on the Meteor Lake iGPU Discord's GPU process aborts every few
  minutes. Its self-update is removed too, or it would put DrDc back.
- **Not Vesktop**: it doesn't run OpenASAR, and the official client is what
  mutectl's plugin was written against.

## Num Lock (numlock module)

- **Plymouth's LUKS prompt**: since version 22 Plymouth reads keyboards
  itself (evdev + xkb) with Num Lock off, whatever the console says.
  `plymouth.use-legacy-input` on wandersail's cmdline makes it read tty1
  instead, where the `sd-numlock` initramfs hook has turned Num Lock on.
  Plymouth's main branch now takes tty1's Num Lock as its starting state; once
  Arch ships that, the cmdline flag can go (the hook already runs before
  Plymouth starts).
- **The Plasma Login greeter** runs KWin as the `plasmalogin` user, whose home
  is private: `/etc/xdg/kcminputrc` sets the default for every account instead.

## Left out of the NixOS port (work laptop)

- **konsave, CUPS, the monochrome emoji font**: not needed (no printer).
- **The NPU driver** (`intel-npu-driver`): nothing uses it.
- nixos-hardware's `hp-probook-460G11` module is covered by the laptop
  module: thermald, fstrim, microcode, i915 early (mkinitcpio's `kms` hook),
  and the Intel media and compute runtimes.

## Nalthis theme (in progress)

Our dark, rounded theme for Plasma 6.8, in `modules/nalthis/`, used by
wandersail. Design page with the research and choices so far:
https://claude.ai/artifact/RWy7GszZyTmP19Q9hXr9sF (private).

- **Choices so far** (Oct 2026): Nocturne greys (hue 255, low tint), blue accent
  (hue 250), radii 12 window / 10 popup / 6 controls, glass only on Plasma's
  panel and popups, Tela (square) color icons with our own line icons drawn
  from Lucide, Breeze cursor.
- **Application style = Breeze (Union) plus overrides**, not a fork: the Union
  style imports Breeze and changes variables and a few rules. A fork would be
  3,000 lines to merge every Plasma release.
- **Installed in `/usr/local/share/union/styles/nalthis`** so it can import
  Breeze by a relative path, like KDE's own Breeze Mobile. An absolute
  `@import` breaks Breeze's own relative imports, and Dolphin then segfaults.
- **Colors live only in the color scheme.** Union reads them from it, so a new
  scheme recolors running apps (tested): the hue / tint / depth / accent knobs
  can be live without touching the style. `pkg/` (Go, `nalthis colors`) is the
  generator.
- **Two ways to move the knobs, one engine**: the "Nalthis Palette" page in
  System Settings (Colors & Themes) and `nalthis tune` in a terminal. Both
  call `nalthis`, preview live and save to `modules/nalthis/palette.json` in
  the repo, so a tweak is never only on the machine. A lodestar hook applies
  the palette when the module changes.
- **Live apply without `plasma-apply-colorscheme`**: it refuses to re-apply
  the scheme already set. `nalthis apply` merges the color groups into
  kdeglobals itself and sends what KDE sends: KConfig's `ConfigChanged`
  (signature `a{saay}`, recorded with `busctl monitor`; with any other
  signature apps keep their cached colors) and KGlobalSettings'
  `notifyChange(0, 0)`.
- **Our own window decoration** (`pkg/decoration/`, KDecoration3 in C++,
  modelled on Breeze's): tiles for minimize / maximize / close (the close
  tile fills the corner, red on hover), square ghost buttons on the left like
  the toolbar's, centered title, title bar merged with the toolbar, 12 px
  corners, square when maximized or tiled. Not Aurorae: it can't declare a
  corner radius, so KWin wouldn't round the bottom corners, and its SVG
  shadows can't blur. Colors come from the scheme, so the sliders recolor
  it. It honors Breeze's "hide title bar" window exceptions (breezerc), so
  `breeze-exceptions:` still works for Konsole, mpv and Spotify.
  Its glyphs are drawn at 1.5 px: the 1 px of KDE's icon rule looked too
  thin next to the title text.
- **Plasma style generated, not drawn** (`pkg/plasma.go`, `nalthis
  plasma-theme`, run at package build): panel, popups (10 px), tooltips
  (6 px) and the popup header are SVG frames computed from a radius, an
  opacity and a shadow size, with the decoration's hairline outline. Only
  those files: everything else (buttons, highlights) falls back to Breeze.
  Colors come from the scheme's classes, so the sliders recolor them live
  (tested). Glass (80%) only in the `translucent/` variant, used when KWin
  blurs; without blur it would be hard to read, so the others are opaque.
  The popup header is the popup's own glass with a hairline, like the
  windows' merged header. The panel is docked and always translucent
  (`plasmashellrc` in the host file: the panel's number is the machine's).
- **The settings page is C++ only where KDE requires it**: a System Settings
  page must be a compiled plugin, so `pkg/kcm/` is a thin C++ shell around
  QML that runs `nalthis`. It builds with Qt's moc and rcc plus g++ (no CMake);
  moc needs KDE's include paths to expand the plugin macro.
- **Calm chrome, not islands**: content views are the darkest surface,
  windows one step up, the header (toolbar merged with the title bar) one
  more. Rounded "islands" were the first pick, but Union 6.8 can't draw them:
  QtWidgets views (Dolphin) paint their own background, and Kirigami pages
  take an inset but no radius. Only square panes with gaps were possible,
  which read as plain dividers and clipped Dolphin's status label. Worth
  another look if a later Union rounds page backgrounds (Kirigami apps only).
- **Two accents of one hue**: a deep one (OKLCH L 0.56) fills checked boxes,
  switches, sliders, focus and the menu hover, with light text on it (~4.5:1);
  a light one is for accent text and links. Fills can't be pale: Kirigami
  draws text and marks on them in the scheme's light text, whatever the CSS
  says. The scheme's selection color is the deep accent too, since KDE uses
  it as "the accent" (Breeze folders, Plasma); the style draws selected list
  rows as a dark accent tint under normal text instead.
- **No filled primary button**: Union's QtWidgets backend reports every
  dialog button as highlighted (Qt makes them all auto-default), so System
  Settings' Help / Defaults / Reset would fill like Apply.
- **Union 6.8 bugs we live with**: QtWidgets menus misalign entries without
  an icon (they start at the left edge), and QtWidgets progress bars draw
  their percentage over the bar.
- **CSS variables**: a color variable defined from another variable in the
  same `:root` doesn't resolve for text, so text colors spell out their
  `custom-color(...)`.
- **Icons: color for things, lines for commands** (`pkg/icons.go`, names in
  `pkg/icons.txt`). Apps, file types and large folders are Tela's (square,
  dark variant); commands (toolbars, menus, buttons), the menu categories and
  the small place and device icons (sidebars, where Tela draws lines too)
  are Lucide, redrawn per size with lines on pixel centers (the 22 px size is
  Lucide's 24 grid minus its empty border: exact) and recolored by KDE like
  Breeze's. Strokes are 1.5 px, not KDE's 1 px: 1 px looked thin next to
  Tela and the text, and 1.5 matches the title bar glyphs. Unmapped names
  fall back to Tela's own line icons, then Breeze Dark.
- **Tela is linked inside our icon theme, not inherited**: icon lookups take
  the closest size within a theme before trying the next one, so with Tela
  inherited, a folder at 64 px would get our 16 px line icon scaled up. Inside
  one theme, our fixed 16/22/24 folders come first and Tela's scalable ones
  serve the rest. Lucide comes from npm at build time (pinned, checksummed);
  Tela from the AUR, which is why lodestar now installs AUR packages before
  building local ones.
- **Testing never touches the session**: `dev/test.sh` runs an app in a
  headless KWin with its own D-Bus and a copy of the config. Galleries of
  every control: `dev/gallery/kirigami.sh` (QtQuick, run through test.sh)
  and `dev/gallery/grab.sh` (QtWidgets, rendered offscreen, since Wayland
  won't open a menu without real input).
